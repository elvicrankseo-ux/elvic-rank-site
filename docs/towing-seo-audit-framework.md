# Towing SEO Audit Framework

A repeatable diagnostic used two ways: (1) to qualify and score a
towing prospect before outreach (see
`docs/elvic-rank-prospecting-machine.md`'s lead-scoring model, which
pulls directly from this framework's findings), and (2) as the free
audit delivered to a prospect who responds — a real, specific piece of
work, not a template dumped on them unread.

**Every finding must be something actually observed** — this document
defines *what to check and how to score it*, not results for any real
business. Never fill in placeholder findings and present them as if
they came from a real audit.

## How to Use This

For each prospect: work through sections A–G, record what's actually
observed for each item, assign a priority, and produce a short
findings summary (Problems → Opportunities → Priority → Recommended
Action → Business Impact) — this becomes both the internal
qualification record and, lightly edited for tone, the audit a
prospect receives.

**Priority key:** P0 = critical (actively losing calls/visibility
right now) · P1 = high (meaningful, addressable gap) · P2 = medium
(worth fixing, not urgent) · P3 = low (minor or cosmetic).

## A. Google Business Profile

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Listing exists and is claimed | Search the business name + city; confirm a claimed (not "unclaimed") listing | P0 |
| Verification status | Verified vs. pending/unverified | P0 |
| Primary category | Specific and accurate (e.g. "Towing Service") vs. generic/wrong | P1 |
| Service-area configuration | Configured as a service-area business with an accurate radius, not a single misleading address | P1 |
| Business info accuracy | Name/phone/hours current and correct | P0 |
| Services list | Specific, matches what the business actually offers, not blank or generic | P2 |
| Photos | Real, recent photos of trucks/team/work vs. none or stock-looking | P2 |
| Review count & recency | Volume relative to visible local competitors; how recent the most recent reviews are | P1 |
| Review responses | Owner responding to reviews (especially negative ones) vs. no responses | P2 |
| Posts/Q&A activity | Any recent activity vs. dormant since setup | P3 |
| Website link | Present and pointing to a live, working site | P1 |

## B. Website

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Mobile usability | Loads and reads cleanly on a phone-width viewport, no horizontal scroll | P0 |
| Page speed (observed, not fabricated) | Note actual load behavior observed directly (e.g. via browser Network tab) — never invent a Lighthouse/PageSpeed number without running the tool | P1 |
| Title / H1 | Present, relevant, not missing or duplicated across pages | P1 |
| Service coverage | Pages exist for the towing services actually offered, or all services are at least described on one page | P2 |
| Location/service-area info | Service area clearly and accurately stated somewhere on the site | P2 |
| Phone number visibility | Click-to-call number visible without scrolling, on every page | P0 |
| Other contact options | Form, WhatsApp, or equivalent beyond just a phone number | P2 |
| Trust elements | Any real, non-fabricated trust signal — licensing/insurance mention, years operating, service-area map, real reviews embedded | P2 |

## C. Local SEO

| Check | What to look for | Typical priority if failing |
|---|---|---|
| NAP consistency | Name/address/phone match across the website, GBP, and any visible directory listings | P1 |
| Citation presence | Listed on at least the major, relevant directories | P2 |
| Local relevance signals | Site content actually mentions the real service area/cities served | P2 |
| Service-area targeting | GBP and website service-area claims agree with each other | P1 |

## D. On-Page SEO

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Keyword targeting | Pages reasonably target real search terms for the services offered, not stuffed or absent | P2 |
| Service page structure | Clear H1/H2 structure per page, not a single wall of text | P2 |
| Internal linking | Pages link to each other sensibly (e.g. homepage to service pages) | P3 |
| Content quality | Specific to the actual business, not obvious generic filler | P2 |
| Search-intent match | Page content actually answers what someone searching that term wants | P1 |

## E. Technical SEO

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Indexing | Pages actually appear in a `site:domain.com` search | P0 |
| Sitemap | `/sitemap.xml` exists and is reasonably complete | P2 |
| Robots.txt | Not accidentally blocking the whole site | P0 |
| Canonical tags | No obvious duplicate-content/canonical conflicts | P2 |
| Broken links | Spot-check primary navigation and CTAs | P1 |
| HTTPS | Site loads securely, no mixed-content warnings | P0 |
| Mobile rendering | No layout breakage at common phone widths | P0 |

## F. Competitive Analysis

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Local Pack competitors | Who actually shows in the map pack for the prospect's core service + area searches | Informational — feeds strategy, not a "fail" |
| Competitor GBP strength | Their review count/recency and profile completeness vs. the prospect's | Context for opportunity sizing |
| Competitor website quality | Do they load fast, have clear CTAs, real service pages | Context for opportunity sizing |
| Content gaps | Services or areas competitors cover that the prospect's site doesn't mention | P2–P3 depending on size of gap |

## G. Conversion

| Check | What to look for | Typical priority if failing |
|---|---|---|
| Click-to-call | Phone number is an actual `tel:` link, not plain unlinked text | P0 |
| Contact form | Present and functional if the site has one | P2 |
| WhatsApp/alternative contact | Present if the business already uses it | P3 |
| Emergency CTA clarity | If the business does emergency/24-hour work, is that stated clearly above the fold | P1 |
| Overall trust at decision point | Nothing that would make a stranded customer hesitate to call | P1 |

## Turning Findings Into a Delivered Audit

Structure the delivered version as: (1) a short honest summary of what
was actually found — 3–5 sentences, no filler; (2) the 3–5 highest
`P0`/`P1` items, each with what was found and why it matters, in plain
language; (3) one clear next step (a strategy call or a scoped
engagement) — never a hard sell. This mirrors the same "useful answer
→ trust → relevant next step" pattern already used across Elvic Rank's
own informational content (see Phase 25/26/29's repeated findings on
the blog→service funnel).

**Never include in a delivered audit:** invented metrics, a specific
promised ranking or call-volume outcome, or any comparison to a
"typical towing company" statistic that isn't independently verifiable
— only what was actually observed for that specific business.
